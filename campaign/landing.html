Your team's agent skills are drifting apart.

One engineer writes a skill. Teammates copy it into other repos. Weeks later, five versions exist, nobody owns any of them, and one has a curl | bash in it. skillsdrift finds that in 30 seconds. The pilot keeps it from happening again.

The free diagnostic

Run it against your skills directories — no account, no setup:

npx skillsdrift ~/repo-a/.claude/skills ~/repo-b/.claude/skills

You get a report: which skills drifted (with the exact lines), which have no owner, which have no version, which contain risky patterns. It runs locally; nothing leaves your machine.

The pilot — what you get

  • Persistent drift monitoring — every teammate's skills directory checked continuously, not once
  • Skill identity — one canonical object per skill: owner, version, permissions
  • One-command install into Claude Code and Codex from your team's governed registry
  • Usage and traces — which version ran, who changed it, what happened

Who it's for

The engineer who "accidentally owns" the team's AI setup: you introduced Claude Code or Codex skills to your team, they spread repo to repo, and now you're the unofficial person who knows which copy is real. This turns that from a memory game into an object with an owner and a version.

What it is not

Not a marketplace. Not a public skills directory. No compliance certifications. The pilot is early — you'd be a design partner, not a customer on an invoice.
